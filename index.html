The graph

The whole code base, as one graph

Trussel reads your repository on your machine: every package, module, class, function and method, and how they contain, inherit, inject and call each other. The Visualiser page lays it out in lanes for the style it detects, whether layered, MVC, hexagonal, component-based, atomic design or feature-sliced, and you can filter it by role, scope it to a module, or open any node to see its purpose, its class hierarchy and where it sits.

What a graph gives you that a folder tree cannot

  • See the impact before the edit

    Trace any node upstream or downstream, up to five hops, and ask how two nodes connect and whether the path breaks the architecture's direction. Removing something shows every dependent, with file and line, before anything goes.

  • Agents that look things up

    Instead of searching text, an agent asks the graph: the architecture in one call, a module's members, the nodes that already do what it was about to write.

  • Lanes that keep the shape

    Each node sits in its architecture lane. A call that runs the wrong way across the lanes is a flow violation, and agents are told not to add new ones.

  • Done means built

    Work planned in a pass is checked against the next analysis of the code, by the stamps the agent leaves, not by its word that it finished.

A React front end, three ways in

The component tree shows what is inside what. Data flow goes from the whole app to one value: Map, then Focus on a component, then Trace a value to where it is made and what changes it.

Eda

An assistant that answers from the graph

Eda sits in the chat beside Claude Code and Codex, and in a bar you open by tapping Ctrl twice. Ask where something is, who calls it or what depends on it, and Eda answers with Trussel's tools over the graph, showing each tool it used. It never guesses a name, a file or a caller.

  • Opens, finds, traces. Files, symbols, callers and dependencies, by name or by asking.
  • Your choice of model. Your own Anthropic or OpenAI key, kept in the system's keychain, with calls straight to the provider. Or Ollama, LM Studio, or Qwen on this computer.
  • Talk to it. Speech to text and back runs on your computer.
  • Hands the building over. Eda reads and explains. "Ask Claude to…" puts your request in Claude Code's or Codex's box for you to send.
  • A colleague. Eda treats you like a colleague, and expects the same: praise only when it's earned, its own mistakes owned, and a calm line drawn if the talk turns abusive.

Explanations

Ask how it works. Watch it happen.

Ask "how does checkout work?" in Eda's chat, Claude Code or Codex. The model writes the answer as a flow, who calls whom with what, and Trussel checks every step against the graph before anything plays. Then focus mode clears the window and plays it across the lanes, like the one at the top of this page, with a caption for each step.

  • Checked against your code. A step that names something the graph does not have is sent back, with the nodes it could have meant.
  • Starts from the screen. A flow can begin with a tap on a design screen and show the states it causes.
  • Saved and replayed. Saved flows replay with no model, and say so when the code has changed since.
  • At your pace. Step, scrub, read all the steps as text, or click a card for its role and its code.

Let the agent build it

The agent implements the pass from the design, touching only the pass's nodes, and leaves a stamp on each. The next analysis reads the stamps and marks each node implementing or implemented, so you see what was built, and what was not.

MCP

One MCP server, for every agent

The IDE runs its own MCP server on your computer. It answers only on 127.0.0.1, and asks for a secret that changes each time Trussel starts. Claude Code and Codex started from Trussel's chat get it automatically, with nothing written to your ~/.claude, ~/.codex or repository. For an agent you start yourself, run Trussel: Copy MCP Configuration and paste it in.

Every agent that connects gets the same working rules: read the design before editing, keep it simple, change only what the pass covers, check the work against the design, keep the stamps, and never remove anything without your yes after a dry run.

The first time you open it

The beta is not signed by Apple or Microsoft yet, so macOS and Windows ask before they run Trussel the first time.

  • macOS

    Trussel is not notarised by Apple yet, so macOS stops it the first time. One command in Terminal lets it open.

    1. 1
      Install

      Open the .dmg and drag Trussel to Applications.

    2. 2
      Allow it, once

      Open Terminal (⌘ Space, type Terminal) and run:

      xattr -dr com.apple.quarantine /Applications/Trussel.app
    3. 3
      Open Trussel

      From Applications or Spotlight. After you install a newer version, run step 2 again.

    The command removes the “downloaded from the internet” flag from Trussel only, and changes no setting on your Mac. If you put Trussel somewhere other than Applications, change the path. Rather not use Terminal? Open Trussel, then choose Open Anyway in System Settings › Privacy & Security.

  • Windows

    If SmartScreen says it protected your PC, choose More info, then Run anyway. The installer needs no administrator rights.

  • Linux

    sudo apt install ./Trussel-…-linux-x64.deb or sudo dnf install ./Trussel-…-linux-x64.rpm, or unpack the .tar.gz and run trussel.

Questions

Does my code leave my computer?

Analysis runs on your computer, and Trussel sends nothing to a Trussel server. When you ask Eda something, your question and the parts of the graph it needs go to the model you chose. With the model on this computer, nothing leaves it.

Do I need Claude Code or Codex?

No. The graph, the Visualiser page, passes and saved flows work on their own, and Eda works with your own key or a local model. If Claude Code or Codex is installed, Trussel's chat starts it with the MCP server already connected.

Which languages does it read?

Python, Java (Maven and Gradle), TypeScript and JavaScript, including React. Everything each language needs comes with the IDE.

Will my VS Code themes and extensions work?

Trussel is built on VS Code's open source code, so the editor, keyboard shortcuts, settings and colour themes work as you expect, and Trussel's own pages follow your theme. Extensions install from Open VSX.

macOS says it cannot verify Trussel. What do I do?

The beta is not notarised by Apple yet, so macOS cannot check who made it and stops it the first time. Run xattr -dr com.apple.quarantine /Applications/Trussel.app in Terminal once (the three steps), or choose Open Anyway in System Settings › Privacy & Security. Each release lists the SHA-256 of every file, so you can check that your download is the one that was built.

How do I get a newer version?

Download it here: each build replaces the last one when you install it. On a Mac, run the Terminal command again after installing it. Updates from inside the IDE come later.
